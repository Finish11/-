# Журнал изменений

Версия живёт в `package.json`; Android-манифест и заметки релиза берутся из неё
скриптами `scripts/app-version.mjs` и `scripts/release-notes.mjs`. Верхняя секция
этого файла всегда должна совпадать с версией в `package.json` — за этим следит
`npm run test:version`.

**Версия поднимается при каждом изменении приложения — даже при самой мелкой
правке.** Одна команда: `npm run version:bump -- patch` (или `minor`/`major`) —
она меняет `package.json`, `android/app/build.gradle` и добавляет секцию в этот
журнал. Дальше остаётся вписать строку об изменении. CI отказывается собирать APK,
если исходники приложения изменились, а версия осталась уже опубликованной
(`npm run version:guard`). Приложение сравнивает и версию, и номер сборки,
поэтому обновление приходит в любом случае.

## 1.11.8

- **Плитка сервиса больше не остаётся зелёной на прошлом выходном IP.** Человек подтверждал YouTube, потом в VPN-клиенте переключал узел — и «приложение работает · подтверждено» продолжало светиться на главной, хотя выход уже другой. Предупреждение «Выходной IP сменился» существовало, но жило только внутри карточки. Причина: кнопка «Понятно» закрывала карточку, не выбрасывая снимок сети, — список сервисов продолжал видеть старый IP и не замечал смену маршрута (у крестика сброс был, у кнопки нет). Теперь карточка закрывается одним обработчиком, и плитка честно пишет «работало · выход сменился, перепроверьте».
- **VPN без указанного узла больше не теряет отзыв при смене выхода.** Если узел не выбран (`vpn:unknown`), отзыв искался только по точному совпадению IP: после переключения узла в клиенте он пропадал из карточки, хотя относится к тому же VPN. Теперь он находится и помечается «выход сменился, перепроверьте». Для прямого подключения правило прежнее: чужой отзыв не переносим.
- **Каталог не выдаёт список за доступность.** Строка «Активно 75 из 75» стояла рядом с шапкой «сеть не определена» и читалась как «всё открыто». Теперь: «Включено для проверки: 75 из 75 — это про список, а не про доступность».
- **Подпись под замером скорости говорит о деле.** «Повтор бесплатен» рядом с «Замер не состоялся» отвечал не на тот вопрос. Теперь: «Проверьте соединение: замеры по одной точке. Можно выбрать другую точку вручную и повторить».
- Проход «телефона» вырос до 31 шага: добавлен шаг «Смена выхода: подтверждение под вопросом» — подтвердил сервис, сменил выходной IP, плитка обязана пожелтеть и попросить перепроверку.
- Проверки: 201 модульный тест, 25 сквозных на десктопе, 31 шаг «телефона», 0 провалов и 0 замечаний.

## 1.11.7

- **Главный вывод проверки сети больше не обрывается.** Сводка вердикта была жёстко обрезана по двум строкам (`line-clamp-2`), и на телефоне фраза заканчивалась на «Часть подсетей (Cloudflare, CDN) лежит —…». Теперь текст переносится целиком: человек дочитывает, что именно показала проверка.
- **Проверка сети перестала быть непроверяемой.** Мок «телефона» отвечал HTML на любой адрес, включая `/favicon.ico`, поэтому все 75 сайтов честно помечались заблокированными с причиной «вместо значка сайта пришла HTML-страница». Это дефект мока, а не приложения, но из-за него ветка замера в проходе не проверялась вовсе. Теперь мок отвечает по типу файла: 204 на `generate_204`, картинка на favicon, HTML на страницу. Замер даёт настоящий вердикт — «Интернет открыт · 47/75 отвечают».
- **YouTube и ChatGPT описаны тем же правилом, что и мессенджеры.** Для них `app_unconfirmed` («приложение не подтверждено») не ставился: youtube.com получал жёсткий «не открыт», а Telegram рядом — «не подтверждено» при ровно той же причине «ответ не распознан». Теперь все сервисы-приложения ведут себя одинаково, и рядом с YouTube больше нет ложного «не открыт».
- Проход «телефона» вырос до 30 шагов: добавлена проверка настоящего замера сети с условием, что при живом моке ни один сайт не отвечает — это провал проверки, а не «плохая сеть», плюс проверка, что сводка вердикта не обрезана.
- Проверки: 200 модульных тестов, 25 сквозных на десктопе, 30 шагов «телефона», 0 провалов и 0 замечаний.

## 1.11.5

- **Обновление приложения больше не «всегда ошибка».** Проверка обновлений глотала любую сетевую ошибку и возвращала «обновлений нет»: интерфейс не мог отличить «установлена последняя версия» от «GitHub недоступен», а сообщение «Не удалось проверить обновления» было недостижимым кодом. Теперь причина возвращается явно: нет сети, лимит GitHub (403/429), в релизе нет APK, нет номера версии — и каждая показывается своим текстом с подсказкой скачать APK со страницы релиза. У запроса появился таймаут 12 с, иначе кнопка «Проверить» висела десятки секунд.
- Если Android не вернул `downloadId`, карточка сразу говорит об этом, а не пять раз опрашивает несуществующую загрузку и выдаёт «Android не нашёл системную загрузку».
- Карточка обновления и проверка из настроек используют один разбор ответа GitHub; фоновая автопроверка по-прежнему молчит при ошибке и не мешает запуску.
- **Замер YouTube перестал врать «не отдал данные» при рабочем YouTube.** Современная страница ролика отдаёт `signatureCipher` — готовой ссылки на поток в ней нет, а дальше оставались только картинки ytimg по 10–150 КБ: на быстром канале они приходят одним пакетом, цифра получается случайной, а при упоре в таймаут 6 с вердикт был «YouTube не отдал ни байта». Добавлен настоящий источник — крупные файлы с youtube.com (player JS): если ни видеоголовка, ни CDN не дали байтов, замер качает мегабайты с того же хоста и получает честную скорость. Порядок источников прежний (видеоголовка → CDN → крупные файлы → служебные адреса), поэтому уже полученная цифра не подменяется.
- **Успешный замер сам подтверждает сервис.** Раньше замер и статус жили отдельно: человек видел цифру и одновременно «приложение не подтверждено», а после ручного «Работает» статус всё равно не менялся, если в профилях не выбран узел. Теперь замер с цифрой сохраняет подтверждение «работает» на текущем маршруте и внешнем IP, а проверка сайтов учитывает свежие подтверждения: `app_unconfirmed` больше не ставится тому, что заведомо работает.
- **Ручное подтверждение стало возможным без указания узла.** При включённом VPN и пустом выборе узла кнопки «Работает»/«Не работает» были отключены — тап не делал ничего, а подсказки противоречили друг другу («выберите используемый узел» рядом с активными кнопками и строкой «системный VPN выключен»). Теперь маршрут «VPN без указанного узла» (`vpn:unknown`) — полноценный вариант: отзыв привязан к VPN-клиенту, текущему выходу и IP, находится при следующем открытии и не теряется. Тексты приведены в соответствие с поведением.
- Проход «телефона» вырос до 27 шагов: замер YouTube обязан дать цифру, успешный замер обязан подтвердить сервис без ручного нажатия, а обновление — показать прогресс и дойти до установщика. Раньше мок плагина обновления не совпадал с Java, и весь путь «скачать → прогресс → установить» в проходе не выполнялся вовсе.
- Исправлен мок «телефона»: `patch()` вызывал удалённую функцию и падал на любом изменении сети.
- Проверки: 200 модульных тестов, 25 сквозных на десктопе, 27 шагов «телефона», 0 провалов и 0 замечаний.

- Замер YouTube больше не показывает «0 бит»: отказ одного адреса (403/410 у videoplayback — ссылка из страницы живёт минуты) обрывал всю фазу загрузки, и замер заканчивался нулём при работающем YouTube. Теперь отказ касается только этого адреса: соединение переходит на следующий живой, а если видеоголовка не дала данных — цифра берётся с CDN ytimg и честно помечается источником.

Если служебные адреса YouTube не ответили, страница ролика не запрашивается вовсе — сразу короткая проверка CDN.

Для медленного канала (< 0,35 Мбит/с) отдельная пометка «сильное замедление». Показывается, сколько длился замер и задержки до youtube.com и видеоголовки.

- Предохранитель на всю процедуру: если сеть приняла сокет и молчит, замер всё равно заканчивается сам и пишет «YouTube не ответил за 26 с» — раньше промис не разрешался никогда, и экран крутился бесконечно. На это есть тест с транспортом, который не отвечает вообще.
- Сквозной тест замера скорости больше не флакует: он цеплял первый `select` в DOM, а это скрытое поле соседней вкладки. Теперь поле ищется по подписи «Конфиг, который сейчас включён» (тест проходил за 33 с вместо 183 с).

- VPN определяется только по системному TRANSPORT_VPN, сетевые снимки защищены от поздних ответов, смешанный замер при смене сети не сохраняется
- быстрые сервисы проверяют ожидаемое содержимое веб-страницы, а не только favicon; посторонний HTML, Cloudflare и HTTP 403 не считаются успехом

## 1.5.1
- если контрольные адреса не ответили, приложение проверяет представителей групп сайтов и не путает их блокировку с отсутствием интернета
- Clash/mihomo: сохраняются UUID, Reality, WS/gRPC и другие параметры при экспорте; разные узлы на одном адресе не схлопываются
- импорт показывает число записей, совпадающих копий и нераспознанных ссылок — проще проверить ожидаемые 79 узлов
- имена узлов с пробелами без percent-encoding больше не обрезаются

## 1.5.0
- подмена TLS и заглушки отфильтровываются отдельно и никогда не считаются открытым сайтом
- замер ускорен: контрольные адреса параллельно, до 32 проб сайтов одновременно, короткий повтор только при таймауте
- Android различает LTE и Wi-Fi по реальному транспорту, в том числе под VPN
- «Мои сервисы» показаны сеткой в несколько рядов, порядок карточек меняется перетаскиванием
- подписка, узлы, замеры и отчёты сохраняются в нативном хранилище и переживают обновление APK
- разные конфиги с одинаковым хостом больше не теряются; при синхронизации сохраняются пинги и основной узел
- узлы сортируются по пингу; все отвечающие по TCP учитываются, медленные не приравниваются к блоку
- отчётом о замере или сбое можно поделиться через системное меню Android
- в новой установке APK нет демо-замеров, демо-узлов и выдуманных региональных отчётов
