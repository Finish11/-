# Пульс сети — полный исходный код

Готовый сайт на React + Vite + TypeScript с русским интерфейсом. Существующие главная страница, статистика сети и открытые отчёты сохранены. Данные общей ленты находятся в `public/data/reports.json`; вход и сторонний API для просмотра не нужны.

## Получить и запустить проект

На странице «О проекте» нажмите **«Скачать полный код»**. Архив `puls-seti-source.zip` содержит все исходники, настройки, локальные данные и lock-файл. Служебные скрипты редактора, аналитика, `node_modules`, секреты и результаты прошлых сборок в архив не включаются.

Требования: **Node.js 24.x**, npm. Эта ветка зафиксирована в `package.json`, чтобы хостинг не переключал сборку на новую основную версию автоматически. Распакуйте архив средствами ОС либо командой `unzip`:

```bash
unzip puls-seti-source.zip
cd puls-seti
npm ci
npm run dev
```

Адрес для разработки Vite напечатает в терминале. Для обычной работы проекта не нужны `.env`, ключи API, аккаунт GitHub или база данных. Первый `npm ci` требует доступа к реестру npm; это зависимость этапа установки, а не работающего сайта.

## Команды

```bash
# Разработка
npm run dev

# Проверка типов, актуальный архив исходников и production-сборка
npm run build

# Локальная проверка production-сборки
npm run preview

# Проверка стиля кода
npm run lint

# Повторная упаковка только исходников
npm run package:source

# Браузерные проверки: сначала установите браузер и соберите проект
npx playwright install chromium
npm run build
npm run test:ui
```

Готовый сайт находится в `dist/`, точка входа — `dist/index.html`. Архив создаётся без дополнительной ZIP-библиотеки в `public/downloads/puls-seti-source.zip` и при сборке копируется в `dist/downloads/`. Он создаётся из явного списка файлов, без рекурсивного включения самого архива. После изменения исходников повторите сборку — кнопка скачивания отдаст обновлённый комплект.

Тесты проверяют навигацию, фильтры, экспорт, проверки сети, локальную историю, обмен ссылками, загрузку JSON, резервный сценарий при ошибке, мобильную версию и скачивание кода. Сетевые пробы в тестах моделируются; никаких реальных отчётов тесты не публикуют.

## Деплой на Vercel

Из корня распакованного проекта выполните:

```bash
npm ci
npm run build
npx vercel login
npx vercel --prod
```

CLI запросит ваш аккаунт и проект. Используйте настройки **Framework: Vite**, **Build Command: npm run build**, **Output Directory: dist**. Дополнительные переменные окружения не нужны. CLI Vercel устанавливается только для деплоя и не входит в клиентский код.

Файл `vercel.json` уже содержит SPA-маршрутизацию, защитные заголовки и правила кэширования. Пути `/assets/`, `/data/` и `/downloads/` исключены из перенаправления на HTML. Архив возвращается как ZIP, данные перевалидируются, хешированные ресурсы кэшируются надолго.

## Деплой на свой статический хостинг

```bash
npm ci
npm run build
```

Загрузите **всё содержимое `dist/`** в корень сайта выбранного провайдера. На сервере Node.js не нужен. Не открывайте `index.html` через `file://`: маршруты и JSON рассчитаны на HTTP(S). Для публичной работы нужен **HTTPS** — в том числе для безопасного контекста браузера, генерации идентификаторов и буфера обмена.

Настройте сервер следующим образом:

- Существующие файлы раздаются напрямую с подходящими MIME-типами.
- Маршруты `/reports`, `/scan`, `/about` и остальные страницы возвращают `index.html`.
- Отсутствующие файлы `/assets/*`, `/data/*` и `/downloads/*` возвращают 404, а не HTML.
- HTML и JSON перевалидируются; хешированные JS/CSS/шрифты можно кэшировать на год.
- ZIP имеет тип `application/zip`, заголовок скачивания и перевалидацию кэша.
- Включены HTTPS и сжатие ответов; шрифты, скрипты и данные не заменяются внешними CDN.

Для Nginx эквивалентные правила внутри уже настроенного HTTPS-блока `server`:

```nginx
root /var/www/puls-seti;
index index.html;

location / {
    try_files $uri $uri/ /index.html;
    add_header Cache-Control "no-cache";
}
location /assets/ {
    try_files $uri =404;
    add_header Cache-Control "public, max-age=31536000, immutable";
}
location /data/ {
    try_files $uri =404;
    add_header Cache-Control "no-cache";
}
location /downloads/ {
    try_files $uri =404;
    default_type application/zip;
    add_header Content-Disposition "attachment";
    add_header Cache-Control "no-cache";
}
```

На сервере с таким корнем сайта и установленным Nginx публикация подготовленной сборки:

```bash
sudo install -d /var/www/puls-seti
sudo cp -a dist/. /var/www/puls-seti/
sudo nginx -t
sudo systemctl reload nginx
```

Домен, сертификат и системный сервис на вашем сервере настраиваются владельцем; эти команды не регистрируют домен и не выпускают сертификат автоматически. `npm run preview` предназначен для локальной проверки, не заменяет production-хостинг.

## Как работают общие отчёты

Формат файла: объект с `version: 1` и массивом `reports`. Каждый элемент — полный JSON-отчёт из приложения: `version`, уникальный `id`, `title`, ISO-дата `date`, `region`, `operator`, `status`, `total`, `available`, `slow`, `latency`, `demo`, `vpn`, `note`; опционально `groups` и `results`.

В комплекте есть пять **явно обозначенных демонстрационных записей**, а не текущая телеметрия. Для добавления реального замера:

1. Выполните проверку в интерфейсе.
2. Нажмите «Поделиться» → «В общей ленте», проверьте поля, подтвердите согласие и скачайте JSON.
3. Администратор проверяет запись и отсутствие персональных данных, добавляет объект в `reports` файла `public/data/reports.json`.
4. Выполните `npm run build` и обновите сайт. Публикация станет видна всем без аккаунта.

Сохраняйте `demo: true` у примеров, не выдавайте их за реальные наблюдения. Формат ограничен 100 записями и 2 миллионами символов, записи валидируются. Публичный файл — **не база данных**: скачивание JSON и localStorage не отправляют замер другим пользователям автоматически. Администратор также удаляет публичные записи вручную с обновлением сайта.

Новые ссылки на отдельные отчёты содержат сжатые данные после `#`; они читаются без аккаунта и не передают содержимое отчёта серверу в URL-запросе. Ссылка не зашифрована: любой получатель может прочитать данные. Отзыв ранее отправленных копий не предусмотрен. Локальная история хранит до 100 замеров в данном браузере.

## Внешние зависимости и приватность

- React, маршрутизатор, иконки, сжатие ссылок и стили включаются в сборку; шрифты Fontsource становятся локальными WOFF2-файлами.
- При чтении главной, статистики и отчётов нет обращений к внешним API, аналитике, Google Fonts или CDN.
- Внешние запросы к ресурсам каталога выполняются **только после запуска пользователем диагностики**. Без них нельзя проверить доступность этих ресурсов.
- CSP в `index.html` и конфигурации хостинга ограничивает выполнение скриптов своим сервером. В production inline-скрипты запрещены; в режиме разработки meta-CSP снимается для Vite Fast Refresh. Служебные скрипты редактора и записи сессий исключаются из экспортируемого HTML и сборки.
- Регион и оператор вводятся вручную; приложение не запрашивает геолокацию и не определяет IP. Проверяемые сайты и сам хостинг всё равно видят сетевой IP обычного HTTP-запроса. Установите необходимые правила и сроки хранения журналов на своём хостинге.
- Секретные ключи VPN не сохраняются, не попадают в публичные отчёты и не включаются в архив исходников. Не храните секреты в клиентском коде или переменных `VITE_*` / `NEXT_PUBLIC_*`.

## Доступность в России и ограничения

Собственный домен, подходящий хостинг, локальные ресурсы и отсутствие обязательных сторонних API сокращают число точек отказа. **Это не гарантия работы без VPN, отсутствия блокировок или соответствия законодательству.** Ограничения возможны на уровне домена, IP, провайдера и сети.

Перед запуском проверьте доступность домена и хостинга из нескольких целевых сетей, включите HTTPS и продление домена, настройте резервное копирование. С квалифицированным юристом проверьте применимость актуальных требований к данным, локализации, трансграничной передаче, уведомлениям и контенту. Определите политику приватности, модерацию и обработку обращений. Размещение демонстрации на Vercel не подтверждает доступность из России.

Браузерный таймаут не доказывает блокировку: на результаты влияют CORS/ORB, защита сайта, DNS и сеть. Измеряется HTTP-ответ, не ICMP-пинг и не скорость интернета. VPN-каталог хранит метаданные, не создаёт туннель и не делает TCP-пинг. Для фонового мониторинга, реального VPN-клиента и автоматической общей базы нужен отдельный backend.
