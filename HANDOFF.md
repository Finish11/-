# ПульсСети — состояние после прохода 1.5.3

Дата прохода: 6 ноября 2026. Рабочая ветка Arena: `arena/e6ffad86-repo`.
База прохода: `a65bd7b` (1.5.2). Актуальный коммит смотреть через `git log -1 --oneline`.

## Главные правила

- Интерфейс по-русски, спокойные формулировки, мобильная ширина 390 px в первую очередь.
- В APK только реальные сетевые измерения. Ответ-заглушка и чужой TLS не считаются
  доступностью. Нельзя подставлять вывод вместо объяснения.
- В новой установке Android нет демо-замеров, демо-VPN и выдуманных региональных отчётов.
  Демо-набор остаётся только в браузерном предпросмотре и явно помечен.
- Пороги вердиктов и узлов без обоснования не менять. Пинг TCP не доказывает работу туннеля.
- Перед коммитом: `npm run typecheck`, `npm run test:core`, `npm run build`, `npm run build:demo`.
- Пуш только в текущую ветку Arena. Если обычный TLS-пуш падает:
  `git -c http.version=HTTP/1.1 push origin arena/e6ffad86-repo`.
- APK: `gh workflow run android-apk.yml --ref arena/e6ffad86-repo`,
  проверка: `gh release view android-latest`.

## Дополнительный проход 1.5.3

- **VPN только по системе.** `networkInfo.resolveVpnStatus` в native-режиме использует
  исключительно `networkKind().vpn`, полученный из `TRANSPORT_VPN`. Страна IP, hosting
  и proxy-флаги GeoIP не влияют на native VPN-вердикт. Browser-оценка имеет `vpn_source=ip`
  и не записывается как доказанный системный туннель.
- **Актуальный default network.** `ApkUpdaterPlugin` регистрирует собственный
  `registerDefaultNetworkCallback` при `load()`. `onCapabilitiesChanged` использует
  переданные capabilities, Network ID и монотонный sequence; `onLost` старой сети не
  стирает новую. Вызов Capacitor вынесен из synchronized-блока. Стандартный Network
  listener и polling — только запасные триггеры, не источник подписи.
- **Никакого guessed underlying.** Android сам добавляет известные Wi-Fi/LTE transports
  в capabilities VPN. Старый перебор `getAllNetworks()` удалён: рядом могла остаться
  неиспользуемая сеть. Если дан только TRANSPORT_VPN, возвращается честный unknown.
  При внутреннем сбое Java передаёт `systemKnown=false`, а не выдуманное «нет сети».
- **Один снимок и порядок ответов.** `App.tsx` имеет generation для каждого async refresh;
  поздний GeoIP не применяется. При смене транспорта старые IP/город/оператор очищаются
  сразу. `detectNetworkContext` повторяет GeoIP при переходе и сообщает, если сеть
  продолжает меняться. Scanner использует `connection || detectedConn` целиком, без
  смешивания полей разных снимков. В APK GeoIP и сайты используют `CapacitorHttp`.
- **Смешанный замер не сохраняется.** После проб `hasSameNetworkAttribution` сверяет
  системный VPN и LTE/Wi-Fi с precheck. Переход во время сканирования отменяет сохранение
  с просьбой повторить; простая смена IP внутри той же сети не отменяет замер.
- **Доказательство содержимого.** `SiteProof`: app/page/endpoint/opaque сохраняется в
  результате. Старые favicon-пробы ключевых сервисов автоматически переводятся на root HTML.
  ChatGPT/YouTube/Claude/Gemini/Telegram/WhatsApp имеют строгие matchers. Generic HTML
  обязан содержать brand/domain; текст/JSON — лишь endpoint. Cloudflare/captcha/4xx
  остаются неоткрытыми. HTTP/TCP/page не доказывают аккаунт, сообщения или туннель.
- **UI.** QuickPicks различает открытую страницу, ответ адреса, opaque и отказ; статусы
  переносятся без обрезания. У legacy-замера без proof статус «ответ без проверки»,
  а не зелёная страница. Детальный список окрашивает endpoint/opaque/unknown жёлтым.
  Домены Telegram/WhatsApp имеют aliases против дубликатов. В VPN-экране системный
  транспорт важнее hosting GeoIP, а неизвестный VPN не называется прямым подключением.
- **Удалён мёртвый обходной путь.** Старый `scanner.detectCurrentConnection` с
  GeoIP/WebRTC-эвристикой не использовался и удалён. Единый detector — `networkInfo.ts`.
- **Проверки:** 23 core tests, TypeScript, production/demo builds. Puppeteer: прежние
  persistence/import/reorder/filter/long-name/VPN-sort плюс proof после reload на
  320/390/768 px. Android callback и реальные LTE ↔ Wi-Fi переходы обязательно проверить
  на телефоне; Java-компиляция проверяется Android CI, локального JDK в sandbox нет.

## Дополнительный проход 1.5.2

- `siteContent.ts` — чистая проверка HTTP-содержимого. Для ChatGPT нужны признаки
  настоящего приложения (`cdn.oaistatic.com`, backend/auth или характерная разметка).
  Cloudflare/captcha/HTTP 4xx возвращают blocked, а не ok. Посторонний HTML не считается
  успехом даже с `<title>ChatGPT</title>`. Это устраняет подтверждённый источник ложных
  «работает», но проверка сайта по-прежнему не доказывает вход и отправку сообщений.
- В `ScannerView.tsx` фильтр объединяет все неоткрывшиеся сайты. Слова «подмена» в
  основном UI больше нет: есть «не открыт» и «чужой ответ», а note с конкретной причиной
  перенесён на отдельную переносимую строку. `QuickPicks.tsx` пишет «сайт отвечает»,
  а не обещает работоспособность всего сервиса.
- `stateStorage.ts` добавляет envelope с `saved_at`; при восстановлении выбирается самая
  свежая валидная копия. Старый JSON 1.5.x поддерживается. `ApkUpdaterPlugin.stateRead/
  stateWrite` хранит независимую копию через `AtomicFile` в `filesDir`. `localApi.ts`
  пишет Preferences + файл + localStorage и больше не принимает полный сбой записи молча.
  Это защита от сбоя одного хранилища, не от удаления приложения/его данных.
- `ExpandableText.tsx` раскрывает длинные имена узлов и подписок нажатием; по умолчанию
  разрешены две строки. Бегущая строка не используется, чтобы текст не уезжал при чтении.
- Core: 15 тестов, включая настоящий/ложный ChatGPT, свежую копию хранения и legacy JSON.

## Дополнительный проход 1.5.1

- `realScan.ts`: если четыре контрольных адреса не ответили, до полного отказа сети
  проверяются по два сайта из каждой группы. Их успешные результаты используются в общем
  замере. Это устраняет ложное «сети нет», когда заблокированы именно контрольные хосты.
- `subscriptionParser.ts`: Clash/mihomo переводится в общий JSON-представитель узла и
  экспортируется с UUID, Reality, flow, WS path/host и gRPC serviceName. Inline YAML
  разбирается с учётом вложенных карт и экранированных кавычек.
- Результат разбора содержит `source_candidates` и `duplicates_removed`. `localApi.ts`
  пишет в карточке подписки, сколько записей было, сколько копий удалено и сколько не
  распознано; ручной импорт показывает это в toast. Для неподдерживаемых записей ничего
  не выдумывается — их число видно отдельно.
- Ссылки с незакодированными пробелами в имени больше не разрываются. Добавлены три
  регрессионных теста: статистика, блочный Clash и inline Clash. Всего core-тестов: 8.

## Что сделано в 1.5.0

1. **Вердикт и фильтр.** `src/lib/scanner.ts` считает `intercepted` неоткрытым даже в
   старой записи со статусом ok/slow; счётчики и средний отклик это тоже учитывают.
   Сценарий со всеми подменами больше не может стать `OPEN_INTERNET`. В
   `ScannerView.tsx` чип «Недоступны» заменён на «Подмена». Есть регрессионные тесты.
2. **Скорость.** `realScan.ts`: до 32 параллельных проб, первый таймаут 4,5 с,
   повтор 2,5 с только для таймаута. `siteProbe.ts`: четыре контрольных адреса
   выполняются параллельно и ждут первый успех. Пороги ok/slow не менялись.
3. **Тип сети.** Нативный `ApkUpdaterPlugin.networkKind` смотрит
   `NetworkCapabilities` активной сети, а под VPN — доступные не-VPN сети через
   публичный `getAllNetworks()`. Если Android скрывает физический транспорт, приложение
   возвращает `unknown`, а не выдумывает Wi-Fi. `networkInfo.ts` использует нативный
   ответ до стандартного Capacitor Network. `App.tsx` обновляет контекст при смене сети.
   Добавлено разрешение `ACCESS_NETWORK_STATE`.
4. **Мои сервисы.** `QuickPicks.tsx`: сетка 2/3/4 колонки вместо одной прокручиваемой
   строки; перетаскивание за ручку работает pointer-событиями на телефоне, стрелки
   доступны с клавиатуры; порядок хранится в `pulsenet_quick_order`. Подмена подписана
   отдельно. ChatGPT не объявляется обязательно заблокированным: проба проверяет сайт,
   не вход/API/сообщения.
5. **Сохранение после обновления.** `localApi.ts` восстанавливает и сохраняет состояние
   через `@capacitor/preferences` (SharedPreferences), localStorage остаётся резервом.
   Сохраняются подписки и их URL, узлы, пинги, сайты, замеры, профиль и отчёты. При
   обновлении каталог пополняется без сброса пользовательских изменений. Старые версии
   состояние не сохраняли, поэтому уже потерянную подписку восстановить неоткуда;
   после повторного добавления в 1.5.0 она должна переживать следующие обновления.
6. **Подписка и пинг.** Дедупликация учитывает полную ссылку (UUID/ключи), поэтому разные
   конфиги с одинаковыми именем и хостом не исчезают. При синхронизации совпадающие
   узлы сохраняют ID, основной флаг и прошлые замеры. Пинг всех и одного узла переведён
   на единый реальный TCP-connect, 12 потоков, таймаут 4 с. Медленный ответ — degraded,
   не blocked; «отвечают» включает online + degraded. Сортировка «Сначала быстрые»
   включена по умолчанию, можно вернуть порядок подписки.
7. **Отчёты без выдуманной публики.** В Android региональные отчёты — реальные записи
   пользователя с именем и временем, сохранённые на устройстве. Через
   `@capacitor/share` их и текст замера можно отправить в мессенджер или на сайт.
   Общего интернет-фида по-прежнему нет: для него нужен публичный backend, которого у
   автономной APK нет. Интерфейс это прямо объясняет и не называет локальное сохранение
   публикацией в общей сводке.
8. **CI.** Workflow перед APK запускает typecheck, core-тесты и web build. Версия
   обновлена до 1.5.0; release notes переписаны под этот проход.

## Архитектура и ограничения

- `src/main.demo.tsx` + `src/demo/localApi.ts` используются и в браузерном preview, и в
  автономной APK. Ветка `isNativeApp()` определяет отсутствие демо-данных в Android.
- `src/lib/realScan.ts` и `siteProbe.ts` — реальные пробы сайтов через CapacitorHttp.
- `src/lib/nodePing.ts` + `ApkUpdaterPlugin.tcpProbe` — настоящий TCP-connect без VPN.
- Настоящего VPN-туннеля (VpnService + sing-box/xray) нет. QR/export только передают узел
  внешнему клиенту. Никакие TCP-замеры нельзя выдавать за проверку работы через узел.
- Региональные отчёты в APK локальные, не общая карта пользователей. Для общей карты нужен
  отдельно развёрнутый HTTPS backend с модерацией и политикой приватности.
- Проверка сайта ChatGPT не означает доступность авторизации, API и отправки сообщений.
- Нативные сетевые транспорты, установка APK и Sharesheet окончательно проверяются на
  телефоне; в песочнице нет Java/Android SDK и доступа к устройству.

## Проверка и следующий проход

- Обязательный локальный набор: `npm run typecheck`, `npm run test:core` (23/23),
  `npm run build`, `npm run build:demo`, `git diff --check`.
- Browser preview: `npm run build:demo`, затем раздать `demo-dist` на :4173. Пройдены
  320/390/768 px, proof-статусы после reload, reorder, blocked filter, persistence,
  импорт Clash, сортировка VPN и полное раскрытие длинного имени без overflow.
- Android CI запускать на актуальный commit и проверять до `success`:
  `gh run list --workflow android-apk.yml --limit 5`. Release должен указывать на тот
  же commit и содержать свежий `pulsenet-debug.apk`. CI подтверждает Java/Android
  компиляцию, но не поведение конкретной прошивки.
- На телефоне повторить оба перехода LTE → Wi-Fi → LTE и Wi-Fi → LTE → Wi-Fi,
  с VPN включённым и выключенным. Сверить системный VPN, транспорт, IP, Билайн/оператора,
  город и обратное восстановление статуса. Переключиться прямо во время замера:
  смешанный результат должен быть отброшен.
- Проверить ChatGPT Cloudflare/403, YouTube/мессенджеры с заглушкой и обычный favicon:
  зелёная страница допустима только при ожидаемом содержимом; endpoint не означает
  работу приложения. Для полной работы аккаунта/сообщений/видео нужны отдельные тесты.
- После обновления APK поверх 1.5.2 проверить подписку и старые favicon-пробы: они
  должны перейти на HTML без удаления карточек и дубликатов Telegram/WhatsApp.
