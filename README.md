# ПульсСети — анти-шатдаун и VPN-радар

Полностековое веб-приложение (русский интерфейс, mobile-first), которое проверяет,
включены ли **белые списки** мобильного интернета в РФ, работает ли **ТСПУ/DPI** и не
идёт ли **глушение сети**, а также ведёт **мониторинг VPN-подписок и узлов**.

**Скачать для Android:** [pulsenet-debug.apk](https://github.com/Finish11/-/releases/download/android-latest/pulsenet-debug.apk)
— debug-сборка около 5 МБ, Android 7.0+, работает офлайн, подробности в разделе
[Android (APK)](#android-apk).

> Диагноз строится по реальным пробам набора сайтов. Он не является официальным
> источником и не заменяет измерения оператора. Демо-данные есть только в браузерном
> предпросмотре и явно помечены; в APK они не используются.

## Что нового в 1.5.8

- В карточке сервиса можно открыть официальное Android-приложение и вручную подтвердить «работает» или «не работает». Сам запуск не считается доказательством входа, сообщений, видео или игры.
- Результат привязан к сервису, выбранному VPN-узлу и внешнему IP. Совпадение IP другого узла показано отдельно и не даёт этому узлу лишний голос в рейтинге; отзыв о VPN не переносится на прямое подключение.
- Рекомендации VPN учитывают последние подтверждения по каждому сервису, покрытие, отказы, статус и latency, а не только TCP-пинг.
- Фактическая web-проба больше не подменяется сервисным вердиктом: «Сайты», сканер и быстрые карточки используют согласованные `network_status/network_latency_ms`.
- «Сбои» получили общий HTTPS API, durable-очередь доставки, идемпотентный `client_id`, синхронизацию без дублей, объединение ленты, голоса и server-side CRUD своих отчётов. Встроенные демо-примеры не отправляются.
- Состояние каждого отчёта видно явно: «ждёт доставки», «не доставлено», «доставлено», «ждёт удаления». Изменения во время синхронизации не перезаписываются поздним ответом сервера; удалённые отчёты защищены tombstone от повторного создания.
- Общий API можно развернуть в Cloudflare Workers + D1 одним workflow. Express/SQLite и Worker/D1 используют один контракт и один handler; локальный сервер не объявляется развёрнутым автоматически.
- TCP-замеры узлов используют медиану трёх попыток без DNS. В рейтинг скорости попадают только подтверждённые прямые TCP-connect ≥1 мс; VPN/unknown/браузерный relay не выдаются за чистый RTT.
- Сайты проверяются единым HTTP-путём с fallback на главную страницу и одним повтором при отсутствии ответа. HTTP 403/нераспознанный HTML не считается открытой страницей, но и не доказывает подмену провайдером; поздний ответ не перетирает свежий замер.

## Что нового в 1.5.5

- Справочные региональные ограничения ChatGPT/Claude/Gemini больше не участвуют в сетевых паттернах DPI и белых списков: вердикт строится только на фактических пробах.
- Массовый TCP ping в APK обновляет каждый узел и счётчик прогресса сразу, а затем сохраняет всю партию одним локальным обновлением без повторного обхода.
- Автопроверка после импорта подписки получает свежий список узлов напрямую и не зависит от задержки React state.
- Игровой TCP в браузере обозначен как доступный только в APK; отсутствие нативного сокета больше не выглядит как недоступность Brawl Stars.
- Ошибки запроса уведомлений и открытия настроек установки APK получили понятные сообщения.

## Что нового в 1.5.4

- Результаты AI и мессенджеров разделяют веб-страницу и приложение: открытый HTML не доказывает вход, звонки или отправку сообщений, а нераспознанный ответ не доказывает блокировку.
- Для ChatGPT, Claude и Gemini на прямом RU-IP показывается справочное региональное ограничение самого сервиса и ссылка на официальный список поддерживаемых стран; это не автоматический диагноз «блок РКН».
- Медленные прошлые проверки, таймауты и `dpi_target` запускаются первыми в параллельной очереди; итоговый порядок отчёта сохраняется.
- Нативный TCP ping использует `System.nanoTime()` и микросекунды, повторяет субмиллисекундные пробы и показывает `<1 мс` вместо `0 мс`. При активном VPN интерфейс прямо объясняет, почему TCP-connect не является чистым RTT до страны узла.
- При первом входе приложение объясняет и запрашивает уведомления и специальное системное разрешение установки APK. Доступ ко всей памяти не требуется: APK скачивается в app-specific Downloads.
- После вердикта добавлен интерактивный словарь: ТСПУ, DPI, белые списки, шатдаун, VPN, TCP-connect, региональные ограничения и нераспознанный ответ.

## Что нового в 1.5.3

- VPN в APK определяется только по системному `TRANSPORT_VPN` активной сети.
  Смена IP, зарубежная геолокация и hosting-признак при LTE ↔ Wi-Fi сами по себе
  больше не включают статус VPN. В браузере IP-оценка явно отмечена как приблизительная.
- Собственный `registerDefaultNetworkCallback` использует данные
  `onCapabilitiesChanged`; устаревшие события и поздние GeoIP-ответы отбрасываются.
  Wi-Fi/LTE, IP, оператор и город обновляются из одного снимка в обе стороны.
- GeoIP и пробы сайтов в APK идут через один `CapacitorHttp`. Если сеть или VPN
  изменились во время замера, смешанный результат не сохраняется.
- Быстрые сервисы проверяют веб-страницу, а не только favicon. Для ChatGPT, YouTube,
  Claude, Gemini, Telegram и WhatsApp есть строгие признаки собственного содержимого.
  Обычный HTML также должен содержать признак запрошенного сайта.
- Результаты разделены на «страница открыта», «только адрес отвечает», «ответ без
  проверки» и «не открыт». Это не обещание работы аккаунта, сообщений, звонков,
  видео или VPN-туннеля. Статусы полностью переносятся на узком экране.
- Добавлены регрессионные тесты сетевых переходов и классификации содержимого;
  прежние проверки подписок, хранения и длинных имён сохранены.

## Что нового в 1.5.2

- ChatGPT проверяется по содержимому приложения: Cloudflare, captcha, HTTP 403 и
  посторонняя страница больше не показываются как работающий сервис.
- Фильтр «Подмена» заменён на «Не открылись». Заглушка подписана «чужой ответ»,

  Все три переживают обновление поверх, но Android удаляет их при удалении приложения.
- Длинные названия узлов и подписок показываются до двух строк и раскрываются нажатием.

## Что нового в 1.5.0

## Что умеет

**Главный экран (мобильный сценарий)**
- Одна большая кнопка «Проверить сеть»: определяет сеть/оператора/ASN, наличие VPN,
  прогоняет 75 сайтов и выдаёт вердикт.
- Если обнаружен VPN — предупреждает и предлагает либо выключить VPN и перепроверить
  доступ по сотовой сети, либо продолжить проверку через туннель.
- Вердикты: `WHITELIST_ACTIVE` (есть белые списки), `DPI_THROTTLING` (ТСПУ),
  `TOTAL_JAMMING` (глушение/шатдаун), `SEVERE_RESTRICTIONS`, `OPEN_INTERNET`.
- Детализация по 6 группам сайтов + разбор каждого домена, заметка к замеру,
  экспорт отчёта для Telegram.
- В браузерном предпросмотре остаются помеченные демо-пресеты; в APK только реальные пробы.

**Каталог сайтов (CRUD)**
- 75 ресурсов с ролями `ru_whitelist` (24), `global_neutral` (24), `dpi_target` (27).
- Добавление/правка/удаление, включение-выключение, одиночный пинг, сброс к базе.
- Фильтры по статусу и категории, поиск по названию и домену.

**VPN-клиент (как Hiddify / v2rayNG / Streisand)**
- Подписки (subscription URL): добавление, обновление, удаление, автоапдейт по часам.
- Импорт одиночных ссылок и base64-подписок: VLESS/Reality, VMess, Trojan,
  Shadowsocks, Hysteria2, TUCI, WireGuard, Clash YAML.
- Узлы: протокол, локация и флаг, хост:порт, пинг по TCP, статус online/degraded/blocked,
  трафик и срок действия подписки, основной узел, RU-каскад, QR для переноса на телефон.
- Демо-подписка из 8 узлов доступна только в браузерном предпросмотре.

**Сбои и белые списки**
- Лента инцидентов по регионам/операторам: тип (белые списки, шатдаун, ТСПУ),
  подтверждения «У меня так же», фильтры, CRUD своих отчётов.
- В APK можно подключить общий HTTPS API из этого репозитория: отчёты группы попадут
  в одну ленту, а не останутся незаметно в локальном хранилище каждого телефона.
- Офлайн-очередь и повторная синхронизация используют случайный `client_id`; повтор
  не создаёт дубликат. Устройство имеет собственные credentials и может менять/удалять
  только свои отчёты. VPN-конфиги, внешний IP и подтверждения приложений не отправляются.

**История замеров**
- График «разрыва связи» (доля доступных сайтов РФ vs нейтральных), раскрытие деталей,
  заметки, переименование, удаление. Сеяные замеры есть только в помеченном веб-демо.

**Платформенное**
- Аутентификация: email+пароль (scrypt), cookie-сессия, демо-вход, регистрация.
- SQLite (better-sqlite3) + WAL, сид-данные.
- Единый дизайн: тёмная/светлая тема, адаптивная сетка, нижняя навигация на телефоне,
  скелетоны/пустые состояния, оптимистичные обновления, тосты.
- Автономная демо-сборка в **один HTML** (без сервера) — для показа по ссылке.

## Быстрый старт

```bash
git clone https://github.com/Finish11/-.git pulsenet   # URL работает и после переименования репозитория
cd pulsenet
npm ci

cp .env.example .env        # опционально
npm run db:seed             # data/pulsenet.db из data/seed.db
npm run dev                 # http://localhost:3000
```

Демо-вход: кнопка «Войти в демо» или `demo@pulsenet.ru` / `demo1234`.

### Скрипты

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер Express + Vite в middleware-режиме, порт 3000 |
| `npm run build` | сборка фронтенда в `dist/` |
| `npm start` | продакшн-режим: раздаёт `dist/` + API |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run test:core` | регрессионные тесты вердиктов и парсера подписок |
| `npm run db:seed` | создаёт рабочую базу из `data/seed.db` (`-- --force` перезаписать) |
| `npm run build:demo` | автономный `demo-standalone.html` (один файл, без сети) |
| `npm run preview:demo` | локальная раздача демо-файла на :4173 |
| `npm run android:sync` | демо-сборка + перенос в Android-проект (`demo-dist` → `android/`) |
| `npm run apk:debug` | собрать debug APK локально (нужны JDK 21 и Android SDK) |
| `npm run android:open` | открыть проект в Android Studio |

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | порт HTTP-сервера |
| `NODE_ENV` | `development` | `production` — раздавать `dist/` вместо Vite-middleware |
| `DATA_DIR` | `./data` | каталог с `pulsenet.db` |
| `VITE_COMMUNITY_API_URL` | пусто | HTTPS-база общего API, встраиваемая в web/APK на этапе сборки |

Для Android workflow адрес берётся из repository variable `PULSENET_COMMUNITY_API_URL`.
Если переменная не задана, пользователь может указать сервер вручную на вкладке
«Сбои» → «Подключить сервер». Без него приложение честно показывает локальный режим.

## Деплой

**Docker (рекомендуется для полной версии)**

```bash
docker compose up -d --build
# приложение на http://localhost:3000, база в томе pulsenet-data
```

**Cloudflare Workers + D1 (общие «Сбои», бесплатный тариф при небольших объёмах)**

1. В GitHub Secrets задайте `CLOUDFLARE_API_TOKEN` (Workers Scripts Edit + D1 Edit) и
   `CLOUDFLARE_ACCOUNT_ID`. Токен не попадает в репозиторий и APK.
2. Запустите workflow **Deploy community API** (`workflow_dispatch`). Он создаёт/переиспользует
   D1 `pulsenet-community`, применяет миграции, публикует Worker и проверяет `/api/community/health`.
3. Скопируйте напечатанный `https://…workers.dev` в repository variable
   `PULSENET_COMMUNITY_API_URL` для сборки APK или подключите адрес в «Сбои» на устройствах.

Локально: `CLOUDFLARE_API_TOKEN=… CLOUDFLARE_ACCOUNT_ID=… npm run deploy:community`.
Без секретов скрипт отказывается выполнять деплой. Проверка контракта без аккаунта:
`npm run typecheck:community && npm run test:worker`.

**Любой Node-хостинг (Railway, Render, Fly.io, VPS)**

1. Build: `npm ci && npm run build`
2. Start: `npm run db:seed && npm start`
3. Смонтируйте постоянный диск и укажите `DATA_DIR` на него — иначе SQLite обнулится
   при каждом деплое.
4. Опубликуйте сервер по HTTPS. Для распределённого APK укажите тот же публичный адрес
   в `PULSENET_COMMUNITY_API_URL` или в настройках «Сбоев» на каждом устройстве.
   Используются `/api/community/incidents`; CORS для этого публичного device-based API
   уже настроен. Данные SQLite должны быть доступны только backend-процессу.

**GitHub Pages (только демо, без сервера)**

Workflow `.github/workflows/deploy-demo-pages.yml` собирает `demo-standalone.html` и
публикует как `index.html`. В настройках репозитория: *Settings → Pages → Source:
GitHub Actions*. Получите статичную ссылку вида
`https://finish11.github.io/<имя-репозитория>/` — по ней работает вся вёрстка и мок-API.

CI `.github/workflows/ci.yml` на каждый push проверяет типы, собирает прод и демо,
выкладывает `demo-standalone.html` артефактом.

## Android (APK)

Приложение упаковано в нативный APK через **Capacitor 8**: внутри — автономная
демо-сборка (`demo-standalone.html`), поэтому APK работает без сети и без бэкенда.
Размер ~5 МБ, `minSdk 24` (Android 7.0+), `targetSdk 36`.

**Скачать APK:** [github.com/Finish11/-/releases/tag/android-latest](https://github.com/Finish11/-/releases/tag/android-latest) —
файл `pulsenet-debug.apk`, входит в публичный релиз и качается без авторизации.
Релиз пересоздаётся на каждую сборку, ссылка на файл не меняется:

```
https://github.com/Finish11/-/releases/download/android-latest/pulsenet-debug.apk
```

Сборку ставит workflow **Android APK** (`.github/workflows/android-apk.yml`): на раннере
GitHub, с предустановленным Android SDK. Тот же APK остаётся артефактом запуска
(*Actions → нужный запуск → Artifacts*), но артефакты скачиваются только с авторизацией —
поэтому основная раздача идёт через Releases.

**Установка на телефон:** скачайте и откройте `.apk` на устройстве, разрешите установку
из этого источника (*Настройки → Приложения → Установка неизвестных приложений*).
APK подписан отладочным ключом — для внутреннего тестирования этого достаточно,
для RuStore/Google Play нужен release-ключ (ниже).

**Локальная сборка** (нужны JDK 21 и Android SDK; проще всего через Android Studio):

```bash
npm ci
npm run apk:debug          # → android/app/build/outputs/apk/debug/app-debug.apk
npm run android:open       # или открыть проект в Android Studio и нажать Run
```

**Подключить общую ленту APK.** По умолчанию WebView открывает встроенные ассеты и
локальный API; пользовательские данные сохраняются в Preferences, атомарном файле и
localStorage. Для общих отчётов не обязательно переносить весь WebView на удалённый
сервер: задеплойте backend по HTTPS и соберите APK с адресом API:

```bash
VITE_COMMUNITY_API_URL=https://ваш-домен.ru npm run apk:debug
```

В GitHub Actions используется repository variable `PULSENET_COMMUNITY_API_URL`.
Тот же адрес можно ввести вручную: «Сбои» → «Подключить сервер». Если нужны также
общие аккаунты вместо автономного режима, дополнительно можно настроить `server.url`
в `capacitor.config.ts`; для одной общей ленты это не требуется.

**Release-сборка со своим ключом** (секреты не коммитятся):

```bash
keytool -genkeypair -v -keystore pulsenet-release.jks -alias pulsenet \
  -keyalg RSA -keysize 2048 -validity 10000
```

Пароли и файл ключа положите в GitHub Secrets
(`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`)
и передайте их в `android/app/build.gradle` через `signingConfigs` — либо соберите
`./gradlew assembleRelease` локально и подпишите через Android Studio
(*Build → Generate Signed Bundle / APK*).

**Обновления.** Приложение сравнивает свою версию (`versionName`) с последним релизом
`android-latest` и показывает карточку обновления: список изменений, размер, кнопка
«Обновить приложение». APK скачивается через системный `DownloadManager` и открывается
системным установщиком — для этого объявлено разрешение `REQUEST_INSTALL_PACKAGES`.
При первом обновлении Android попросит разрешить установку из этого источника.

**Что реально работает в APK.** Подписка скачивается нативным HTTP-стеком
(`CapacitorHttp`), поэтому CORS не мешает: вставляйте любой URL подписки — распознаются
все узлы (VLESS/Reality, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, WireGuard, Clash),
подтягивается трафик и срок из заголовка `Subscription-Userinfo`. Кнопка «Проверить»
делает настоящий TCP-connect до каждого узла (4 параллельно, медиана трёх попыток) и ставит статус
online/degraded/blocked с пингом. Главный экран выполняет реальные пробы всех включённых
сайтов через нативный HTTP; заглушки и подмена TLS не засчитываются как доступность.
VPN-туннель приложение не поднимает.

**Чего в APK нет:** гарантированных фоновых замеров по расписанию и настоящего
VPN-туннеля (`VpnService`). Общая лента работает только после развёртывания HTTPS API —
в сам APK публичный сервер не «зашит» автоматически. Локальными отчётами и замерами можно
поделиться через Android. TCP-пинг не доказывает, что через узел откроются сайты.

## Как считается вердикт

1. Берётся включённый каталог, сайты делятся на три роли:
   `ru_whitelist`, `global_neutral`, `dpi_target`.
2. Каждый домен пробуется из браузера (fetch/img с таймаутом), при блокировке —
   через серверный релей. Сайт считается живым, если ответ получен быстрее порога.
3. Считаются проценты доступа по каждой группе → `ru_ok_pct`, `global_ok_pct`, `dpi_ok_pct`.
4. Правила:
   - `ru_ok ≥ 45%` и `global_ok ≤ 40%` и VPN выключен → **WHITELIST_ACTIVE**;
   - `ru_ok < 45%` и `global_ok < 30%` → **TOTAL_JAMMING**;
   - нейтральные открыты, но `dpi_ok` низкий/пинги растут → **DPI_THROTTLING**;
   - часть зарубежных подсетей отваливается → **SEVERE_RESTRICTIONS**;
   - иначе → **OPEN_INTERNET**.
5. Порог «блокировки» узла VPN: DNS-фейл, успех < 50% или средний пинг > 900 мс;
   «замедлен»: средний > 320 мс или худший > 2.5× среднего.

## Известные ограничения / что можно улучшить

- [ ] Пробники в браузере ограничены CORS и таймаутами — часть сайтов нужно мерить
      только серверным релеем (сейчас есть фолбэк, но нет пула региональных релеев).
- [ ] Нет автоматического планировщика фоновых замеров (cron) — замеры только по кнопке.
- [ ] Нет push/Telegram-уведомлений о смене вердикта.
- [ ] Инциденты не модерируются и не дедуплицируются по гео.
- [ ] Нет постоянного e2e-набора в CI; browser/API regression выполняется отдельно
      через headless Chromium и реальный SQLite runtime.
- [ ] Сессии живут в SQLite; для нескольких инстансов нужен внешний стор (Redis).
- [ ] Каталог сайтов статичен в коде (`DEFAULT_SITES`) — редактируется только в UI.
