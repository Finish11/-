# Пульс сети — веб-панель

Адаптивная открытая веб-панель на Vite, React, TypeScript и Tailwind CSS.
Основана на каталоге и демонстрационных данных проекта Finish11/- (MIT).

## Возможности

- Обзор сети, адаптивные графики и контрольные сервисы.
- Реальная ручная проверка HTTPS-доступности из браузера: быстрый набор до 12 ресурсов или весь включённый каталог.
- 75 исходных ресурсов, поиск, фильтры, включение/отключение и добавление своих доменов.
- До 100 замеров в localStorage; просмотр деталей, удаление, экспорт CSV и JSON.
- Ссылки на отчёты с полными сжатыми данными во фрагменте URL после `#`, открываемые в другом браузере без аккаунта. Старые ссылки с параметром `?report=` тоже поддерживаются.
- Общая публичная лента читает локальный `/data/reports.json` с того же сервера. Внешний API и авторизация не нужны.
- Подготовка публикации: проверка данных → подтверждение согласия → скачивание JSON → модерация и размещение администратором. Скачивание само по себе не публикует и не отправляет отчёт.
- Лента наблюдений о частичной доступности.
- Локальный каталог метаданных VPN-узлов, импорт ссылок и base64-содержимого подписок, выбор основного, удаление и экспорт метаданных без секретов.

## Важные границы

Это не запущенная серверная часть оригинального приложения. Для постоянной телеметрии, TCP-пинга, подключения VPN и работы с подписками на сервере необходим оригинальный backend/клиент и постоянное хранилище.

Браузерная проверка не устанавливает причину отсутствия ответа. Режим no-cors не позволяет прочитать HTTP-статус и содержимое ответа. Возможны защитные страницы, CORS/ORB, таймауты и другие ложные негативные результаты. Не следует интерпретировать статус как доказательство блокировки, белых списков или ТСПУ.

Данные первого обзора, демонстрационные отчёты и VPN-статусы явно отмечены. Почасовой график до реальных замеров иллюстративный. Реальные замеры не публикуются автоматически.

Лента статическая: сервер приёма публикаций и общая база для автоматической записи здесь не развёрнуты. Администратор добавляет проверенные JSON-записи в `reports` файла `public/data/reports.json`, сохраняя `version: 1` у файла и каждой записи, уникальный `id` и явную метку `demo`. Файл ограничен 100 записями и 2 миллионами символов, каждая запись валидируется. После `npm run build` и публикации папки `dist` новые записи доступны всем. Удаление localStorage не удаляет публичный файл или копии в ссылках; публичную запись удаляет администратор из исходного JSON с последующим обновлением сайта.

## Приватность

Панель не определяет IP и не запрашивает геолокацию. Регион и оператор вводятся вручную. Внешние диагностические запросы выполняются только по действию пользователя; проверяемые сайты видят сетевой IP, cookie в пробах не отправляются. Ключи VPN не сохраняются; сохраняются только имя, хост, порт и протокол. При чтении ленты нет обращений к GitHub API, CDN, внешним шрифтам или аналитике. Фрагмент новой ссылки на отчёт не входит в HTTP-запрос, но доступен любому получателю ссылки и не зашифрован. Хостинг может вести обычные журналы запросов; их настройки, основания обработки и сроки хранения определяет владелец сайта.

## Проверки

- `npm run build` — TypeScript и production-сборка.
- `npm run lint` — ESLint.
- `npx playwright install chromium` — установка браузера для тестов.
- `node scripts/qa.mjs` — конечный тестовый процесс со временным статическим HTTP-сервером: интеграционные проверки, скриншоты desktop/mobile, проверка отсутствия горизонтального переполнения и внешних запросов при чтении страниц. Сетевые пробы и отдельные сценарии локального JSON моделируются; тесты ничего не публикуют.

## Развёртывание

Vercel автоматически собирает Vite-приложение. SPA-маршрутизация и защитные заголовки настроены в `vercel.json`: `/data/` исключён из SPA-перенаправления, JSON перевалидируется, хешированные ресурсы кэшируются на год. Установлены `Referrer-Policy: no-referrer` и запрет DNS-prefetch. Секреты и база данных для текущей архитектуры не требуются. В рабочий репозиторий пользователя изменения не отправлялись.

Для другого статического хостинга перенесите **всю** папку `dist`, включая `assets` и `data`. Раздавайте существующие файлы с правильным MIME-типом, неизвестные пути приложения направляйте в `index.html`, но отсутствующие `/assets/*` и `/data/*` возвращайте как 404. Включите HTTPS, сжатие ответов и аналогичное кэширование; не заменяйте локальные шрифты и скрипты внешними CDN.

## Доступность из России и правовые вопросы

- Собственный домен, контроль DNS, защита аккаунта регистратора и своевременное продление уменьшают операционные риски. Проверьте историю домена и доступность HTTPS у нескольких целевых операторов. Доменная зона не даёт иммунитета от ограничений.
- Выбирайте хостинг с подходящей географией и условиями обработки данных; проверяйте реальные IP-адреса и маршруты из российских сетей. Текущий предпросмотр на Vercel не подтверждает такую доступность; российский хостинг и домен автоматически не настроены.
- До публичного запуска поручите квалифицированному юристу проверить применимость актуальных требований к персональным данным, локализации, трансграничной передаче, уведомлениям и контенту. Подготовьте политику приватности, сроки хранения журналов, модерацию и порядок обработки обращений. Это рекомендации по проверке, а не утверждение о соответствии законодательству.
- Нет технической гарантии, что сайт всегда будет работать без VPN или не будет ограничен по домену/IP. Локальные зависимости сокращают число точек отказа, но не предотвращают решения операторов, регуляторов и сбои инфраструктуры.
