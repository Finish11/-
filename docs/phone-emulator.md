# «Телефон»: проход по приложению как человек

Настоящий Android-эмулятор в песочнице не запускается (нет KVM, SDK, adb и сети до
`dl.google.com`), поэтому проверка идёт в Chromium в режиме Pixel 7 с **поднятым
нативным мостом Capacitor**: приложение видит `Capacitor.isNativePlatform() === true`,
заголовки плагинов и ходит в них через `nativePromise`/`nativeCallback` — то есть
идёт по тем же веткам кода, что APK.

## Запуск

```bash
PORT=4173 DATA_DIR=/tmp/phone-data VITE_DEMO=1 npx tsx server/index.ts   # окно 1
npm run test:phone                                                       # окно 2
```

Снимки, журнал шагов и замечания — в `phone-report/` (`report.json`, `README.md`, PNG).
Адрес задаётся через `PHONE_URL`, каталог снимков — через `PHONE_OUT`.

Открывается **`demo.html`**, а не `/`: APK упаковывает именно его
(`scripts/android-assets.mjs` копирует `demo.html` в `index.html`), и только там
`/api/*` обслуживает локальный API из `src/demo/localApi.ts`. Если проверять
`index.html`, тестируется ветка живого сервера, которой на телефоне нет.

## Что уже проверяется (24 шага)

- первый запуск и шит разрешений;
- все шесть вкладок + проверка горизонтального переполнения и кнопок без подписи;
- замер скорости: живые сэмплы трассы, пик, задержка «под нагрузкой»;
- замер YouTube и вердикт качества;
- **выключение VPN**: шапка обязана вернуться на прямой маршрут;
- **пропажа сети**: замер заканчивается отказом с причиной, а не «0 Мбит/с»;
- **точка замера отвечает 403**: показывается код, результат не обнуляется;
- светлая и тёмная темы (через шестерёнку, с проверкой класса `light`);
- каталог сайтов: поиск по названию;
- «Скопировать отчёт»: текст реально попадает в буфер;
- форма сбоя: отчёт сохраняется и появляется в списке;
- «История замеров» на экране скорости: результат действительно сохранён;
- подписи всех селектов влезают в поле (WebView режет длинный текст без многоточия).

## Как устроено

| Файл | Роль |
|---|---|
| `tests/emulator/phone.ts` | init-скрипт: заголовки плагинов, «Java»-ответы, события, `window.__phone` |
| `tests/emulator/device.ts` | `openPhone()`: Pixel 7 412×915, dsf 2, `step/note/shot/tap/visible/layoutCheck` |

| `tests/emulator/run-phone.ts` | сам проход: моки GeoIP и Cloudflare + сценарии |

Управление «телефоном» из теста:

```ts
phone.tap('Проверить сеть', { exact: true });
phone.visible('Готово');
await phone.shot('screen');
phone.layoutCheck('экран');
phone.note({ severity: 'minor', area: 'скорость', title: '…', detail: '…' });

// Сеть и VPN на «телефоне» — как системные события Android.
await page.evaluate(() => window.__phone.setNetwork({ systemVpn: false, appUsesVpn: false }));
```

## Правила, без которых проход врёт

- **`getByRole(...).first()` не годится** — в разметке есть скрытый десктопный
  сайдбар с теми же подписями. Только `phone.tap`/`phone.visible`: они перебирают
  совпадения и берут первое **видимое**.
- **Доступные имена вкладок — из `aria-label`**: «Проверка сети», «Каталог сайтов»,
  «Сбои и белые списки», а не «Проверка»/«Сайты».
- **События сети — только через `setNetwork()`**: он поднимает `sequence` и шлёт
  `networkChanged`, как `NetworkCallback` в Android. Прямая правка состояния
  события не рождает, и приложение (правильно) ничего не перепроверяет.
- **Слушатели хранятся по `callbackId`**, как в Java: React StrictMode монтирует
  эффект дважды, и отписка «старого» монтирования не должна снимать живое
  событие.
- **Ответы `CapacitorHttp` зависят от хоста**: JSON для GeoIP, HTML для YouTube,
  403 для заблокированных хостов, DNS-ошибка без сети.

## Найденные и исправленные дефекты

| Дефект | Причина | Исправление |
|---|---|---|
| Шапка навсегда «определяем сеть…» | мок отдавал `sequence: Date.now()` — приложение видело смену сети на каждом опросе | монотонный `sequence`, рост только при реальной смене |
| «пик 1 Мбит/с» при итоге 62 | нативная фаза не отдавала живые сэмплы | срезы в `speedRunner.phase` + итоговый срез из `nativeSpeedPhase` |
| «нагрузка не измерена» на быстром канале | проба «под нагрузкой» стартовала с задержкой 20 % бюджета и не успевала | старт через ~300 мс, пока фаза жива |
| Одна ошибка показана дважды | баннер на месте + тост тем же текстом | тост при отказе замера убран |
| «Ошибка запроса (404)» при сохранении отчёта | `PUT /api/incidents/cache` падал и срывал сохранение | кэш ленты стал необязательным, отчёт сохраняется локально |
| События `networkChanged` не доходили | в заголовках не было `addListener`, слушатели хранились по имени события | заголовки как в Java + подписки по `callbackId` |
| Шит настроек перекрывал навигацию | шаг не закрывал шит | закрытие «Готово» + проверка |
| Вкладка «VPN» в проходе открывала каталог | `/VPN/` находил слово «VPN» внутри чужого экрана | тап по `aria-label` + проверка `aria-current` и заголовка |
| «Автоматически (свой сервер → Cloudfla…» | подпись шире поля селекта | короткие подписи + проверка ширины текста в проходе |

## Ограничения

- Сеть синтетическая: скорость, задержки и блокировки задаются моком, а не реальным
  каналом. Проверяется логика приложения, а не качество вашей сети.
- Настоящие Android-вызовы (установка APK, системные диалоги, буфер обмена вне
  WebView) не воспроизводятся — для них нужен реальный устройство или KVM.
- `ERR_CERT_AUTHORITY_INVALID` в консоли — запрос мимо мока (проверка релиза на
  GitHub), в песочнице внешней сети нет.
