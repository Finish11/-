## Что нужно сделать для переноса (по шагам)

1. **Проверить, что вся работа в GitHub.** В новой сессии локальная история снова
   откатится к базе ветки, поэтому в ней нет смысла хранить что-то только на диске.
   ```bash
   git fetch origin arena/fcf07acb-repo
   git status --short          # должно быть пусто (кроме временных файлов)
   git log --oneline -1        # сверь с ожидаемым коммитом
   ```
   Если ветка отстаёт от диска — закоммить и запушь до передачи.
2. **Открыть новый чат** в тот же репозиторий (Arena привязывает сессию к ветке
   `arena/fcf07acb-repo`). Ветку не переименовывать и не переключать.
3. **Вставить промпт ниже** первым сообщением — целиком, одной вставкой.
4. **Дать новому чату восстановиться** (~2 минуты), он сделает это сам:
   ```bash
   git fetch origin arena/fcf07acb-repo
   git reset --hard origin/arena/fcf07acb-repo
   npm ci --no-audit --no-fund --ignore-scripts
   npm rebuild better-sqlite3 --nodedir=/usr/local
   ```
5. **Сказать первую задачу** — например «продолжай проверку телефоном» или
   конкретный баг. Без задачи новый чат начнёт с общей проверки.

Подключённые приложения (Google Docs/Drive) переносятся на уровне чата, а не промпта:
их нужно заново включить в новом чате, если они нужны.

**Все проверки идут через «телефон» — Playwright-эмулятор телефона, а не через вызовы функций.**
Действуй как пользователь: тапай по UI, читай, что видно на экране.


Реальный Android-эмулятор здесь **невозможен**: нет `/dev/kvm`, `vmx|svm` = 0,

это Chromium в режиме Pixel 7 с поднятым нативным мостом Capacitor: приложение считает
себя APK и идёт по тем же веткам кода. Подробности — `docs/phone-emulator.md`.

## Окружение: обязательные грабли

После каждого нового сообщения git-история может откатиться к базе ветки (`ba130f0`),
а файлы на диске останутся новыми. Порядок восстановления:

```bash

git reset --hard origin/arena/fcf07acb-repo   # рабочая копия = origin
npm ci --no-audit --no-fund --ignore-scripts
npm rebuild better-sqlite3 --nodedir=/usr/local
```

- `npm ci` ~15 с, `npm rebuild better-sqlite3` ~1 минуту. Без rebuild падают server-тесты.
- `git status` может врать (показывает 100 изменений при целом дереве) — сверяйся
  с `git diff origin/arena/fcf07acb-repo`, а не с индексом.
- Если push отклонён — сначала `git fetch`, затем cherry-pick своей работы поверх origin.
  **Никогда не делай force-push.**
- `npm test` не существует — только наборы: `test:core`, `test:speed`, `test:routes`,
  `test:scan`, `test:version`, `test:sync`, `test:regressions`, `test:native`, `test:worker`.
- `test:e2e` **конфликтует с демо-сервером на 4173** — сначала останови его.
- Открывать надо **`demo.html`**, а не `/`: APK упаковывает именно его.
- `npm run test:phone` требует запущенного демо-сервера; `DATA_DIR` даёт чистую базу.
- Внешней сети нет: только `github.com`, `codeload`, `api.github.com`, `registry.npmjs.org`,
  `pypi`. Значит, живые проверки — только через `page.route`; `ERR_CERT_AUTHORITY_INVALID`
  в консоли ожидаема.

## Процедура выпуска версии

```bash
npm run version:bump -- patch "Короткое описание"
# затем вписать раздел в CHANGELOG.md и обновить docs/phone-emulator.md (число шагов)
npm run test:version        # верхняя секция CHANGELOG обязана совпадать с package.json
npm run build && npm run build:demo
git add -A && git commit -F /tmp/msg.txt
git push origin arena/fcf07acb-repo
```

- Версия поднимается **при каждом изменении приложения**, даже мелком. CI не соберёт APK,
  если версия не выросла (`npm run version:guard`).
- После пуша проверь прогоны: `gh run list --limit 4`. Бывает, что GitHub не доставляет
  событие в Actions — тогда APK запускается вручную (`gh workflow run android-apk.yml
  --ref arena/fcf07acb-repo`), а для CI нужен пустой коммит (ручного триггера у него нет).
- Релиз проверять так: `gh release view android-latest --json name,assets`.
  Сборка APK сама публикует тег `android-latest`.
- `gh release view` показывает body из `scripts/release-notes.mjs` — он берёт раздел CHANGELOG.

## Как найти настоящую причину, а не симптом

Эти правила выведены из реальных ошибок в этом проекте:

- **Тест может закреплять баг.** Дважды тесты дословно защищали дефект («для прямого
  подключения смена IP — другая сеть, отзыв не переносим»). Если тест падает после
  осмысленной правки — сначала прочитай, что он утверждает, и реши, кто прав.
- **Мгновенный вердикт ≠ скана не было.** Проверяй число вызовов и текст «прошло N с».
- **`offsetParent === null` не значит «скрыто»** внутри `position: fixed`.
- **Кнопка может менять имя** после действия («Проверить сеть» → «Повторить замер сети»).
- **Шторка сервиса перекрывает экран** — перед тапом по вкладке закрывай её `Escape`/«Понятно».
- **`getByText('YouTube').first().click()` таймаутит** — открывай плитку через `page.evaluate`
  и `closest('button,[role="button"],div[class*="rounded"]')`.
- Правки в файлах делай через `python3 - <<'PY'`, а не heredoc с обратными кавычками.
- Плитки сервисов имеют `data-quick-id` (`[data-quick-id="telegram"]`) — читай текст оттуда,
  а не поиском по всему `body`: иначе поймаешь баннер вместо плитки.
- **Мок игнорирует `patch({ip})`** — выход меняется только через `patch({exitIp})`/`directIp`,
  VPN включается/выключается через `__phone.setNetwork({systemVpn, appUsesVpn})`.
